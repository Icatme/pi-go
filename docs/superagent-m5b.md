## 信任边界

- 对限长原始 body 进行 SHA-256 HMAC 常量时间比较；解码前验证，不重新编码。
  拒绝重复关键头、重复 JSON 键、非法 Unicode、编码 body 与含糊事件形状。
- 签名不授予任何业务权限。精确 repo ID/PR 允许列表、宿主 sender/意图授权与
  协调器 actor policy 分开验证。维护者编辑时 sender 是当前编辑者，原作者不授予权限。
- GitHub HMAC 不覆盖 delivery/event 头，也没有签名时间。使用原始 body SHA-256
  作为持久准入 ID，保留原 delivery/event 头、原始 body 与 hash 给宿主审核。
  修改未签名 delivery 头无法重放；支持的 event 头必须与唯一 body 形状一致。
- 相同签名字节始终保守视为已观察，返回 `ErrGitHubReplay` 与当前原始证据、可用的
  原准入回执，不静默当成成功新事件。宿主授权变化不能替换已冻结的路由决定。
  合法独立事件若 body 字节完全相同，本适配器无法精确区分，必须人工/平台独立证据
  核实。相同文本但不同签名评论 ID 不会合并。旧签名 body 未曾入日志时仍能通过验签，
  因此不声称防止所有陈旧重放。原始头/body 审计由宿主保存，本包不提供持久 HTTP inbox。
- 入站只准入，不发送。出站仅显式 `Adapter.SendReply` 读取已批准内容与目的地、
  持久领取尝试后，向宿主允许的 PR 讨论区创建普通 issue comment。
- API URL、ID→仓库名映射与认证 HTTP transport 由宿主配置；不信任 webhook URL。
  禁止重定向，限长回执、超时；201 的 ID/body/issue_url/url 必须精确匹配。
- 两种限流提示同时出现时取较晚期限，保留一秒裕量并复用源级持久门控。
  含糊/损坏/无提示响应维持 unknown，宿主应暂停进一步流量核实。
- GitHub POST 没有本实现可用的幂等保证，不发送虚假幂等头、不自动重发。
  `Lookup` 不联网、不扫描相同正文评论，不用缺失列表项证明未交付。
  丢失回执、HTTP 错误、超大/非法回执与跨目的地回执保持待核实。

## 验证范围

先记录缺失 API 的失败构建，再实现。真实 `httptest` HTTP 编解码覆盖伪造签名、
签名后改写 body、未签名头篡改、重放/重启、同文不同评论、跨 repo/PR、编辑者权限、
回调失败/突变、明确批准发送、已知回显、丢回执后重启与不重试、错误回执、重定向、
限长、取消和双限流提示。所有密钥为测试自造字节，不是用户凭据。

独立只读审查发现并修复两项合同问题：双限流提示提前重试；同 body 在宿主授权变化后
未返回原始重放回执。补充回归；同时修复超时测试服务未读 body 导致关闭等待的测试问题。
最终全仓 tests、串行 race、vet、examples 模块与独立复审结果以 PR 为准。

尚未验证真实 GitHub/GHES、生产代理/TLS、实际权限、账号重命名/转移、长期凭据轮换、
分布式 HTTP inbox 或平台一致性。本切片不是网络沙箱，宿主 RoundTripper 不得重试
POST，必须正确认证服务并安全注入凭据。无用户本机、真实平台请求、模型调用、Codex/
额外付费执行、手动 CI、合并或部署。[完整合同](../superagent/channel/README.md)。
