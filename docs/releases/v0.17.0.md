Bounded tool arguments, required/nullable tool schemas, protected compaction tails and classified provider failures.

## Changes

- Add host-only `ToolDefinition.MaxArgumentBytes` limits for raw, parsed, normalized and before-hook arguments across direct, model and child tool calls. Unicode rejection preserves the original parser or hook error cause.
- Add `agent/strictschema` to prepare detached required/nullable declarations and normalize optional nulls back to omission. Preserve empty values, required nulls and numeric lexemes; enforce schema and argument bounds. Exact-null matching preserves omission with the default coercing validator and prevents scalar constraints from being bypassed.
- Add `session.CompactionOptions.ProtectedTailMessages` to retain host context and current-run messages, expanding the protected tail to complete turn boundaries.
- Add `pigo.ProviderFailureOf` and classified failure diagnostics for upstream errors, interrupted streams, response parsing and SDK failures. Preserve failure origin through hosted continuation and classify parsing errors at response boundaries.

## Upgrade notes

- Version advances from 0.16.0 to 0.17.0 for the additive public APIs.
- A zero tool argument limit retains the existing per-tool behavior; separate child-call limits still apply. A zero protected-tail count retains the ordinary newest-turn minimum.
- Strict-schema conversion is opt-in and requires ordinary schema validation before normalization. It does not enable a provider's strict mode or replace host authorization.
- Provider diagnostics describe failures; hosts remain responsible for retry policy and protecting untrusted provider error text.

## Validation

On Windows with Go 1.26.4 and `GOWORK=off`, an isolated snapshot containing the release's version changes passed `go test -mod=readonly ./... -count=1` and `go vet -mod=readonly ./...` in both root and examples modules. The examples module resolves this checkout as v0.17.0; a CLI build and the `pigo --help` version banner check also passed. Live-provider tests were disabled. Non-Windows execution and remote CI are not claimed by these local checks.
