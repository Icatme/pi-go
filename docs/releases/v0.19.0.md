# v0.19.0

## Explicit execution receipts

Applications can opt into bounded host-side receipts for direct Agent calls,
standalone Codemode and nonpersistent model runs. Receipts retain reported local
commits after hook failures, cancellation and result rejection, and distinguish
actual executor completion from an early return to the caller.

Use `agent.RunToolCallWithReceipts`, `Sandbox.RunWithReceipts` or
`Runner.RunWithReceipts`. Keep the returned handle until outstanding bodies are
reconciled. A false committed flag means unknown, not proof of no effect.

Session-backed single direct calls persist intent/final receipt records behind
legacy runtime fences. Existing readers can browse the session; unaware legacy
runners return `ErrInterrupted`. This does not add persistent model execution,
checkpoint recovery, automatic retry, deduplication or an atomic transaction
between external effects and session storage.

## Opt-in filesystem and execution tools

`agent/fstools` provides bounded `ls`, `read`, `find`, `grep`, `preview_edit`,
`create_file`, `atomic_replace` and `edit` tools, plus explicit read-only and
workspace-write presets. Writes require a receipt-aware entry point. Linux and
a trusted host workspace are required; read/write operations also rely on the
documented procfs and filesystem capabilities. Other platforms fail closed.
Replacement remains last-writer-wins and can change inode metadata; it is not CAS.

`agent/exectools` adapts host-supplied command and Python executors with input,
combined-output and deadline bounds. It does not locate or start a process or
interpreter. The application supplies isolation and actual termination/reaping.
Context cancellation requests termination; it cannot certify that a backend has
stopped. Only confirmed host reports become committed receipt facts.

## Upgrade notes

- Legacy Engine entry points continue accepting nil contexts. Receipt-boundary
  normalization preserves their existing validation errors instead of panicking.
- Existing public struct layouts, `Tool.Invoke`, events, execution JSON and
  session formats are unchanged from v0.18.0. No tools or external backends are
  enabled automatically.
- Receipts are observations, not a retry barrier. A model or script can issue
  another call after failure, including after a committed effect. Applications
  must provide their own write and retry policy.
- PR #153 supersedes the old filesystem stack (#139–141, #143, #145–149).
  Do not merge those histories or the incompatible #144 afterward.
- Builds require Go 1.26.2 or newer. See the [receipt contract](../../executionreceipt/README.md),
  [direct-session protocol](../../agent/session/RECEIPTS.md),
  [filesystem guide](../../agent/fstools/README.md) and
  [executor guide](../../agent/exectools/README.md).
