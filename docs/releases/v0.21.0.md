# v0.21.0

The `pi-superagent` CLI now uses the persistent main session through
`OpenMain` and `PiMainRouter`. Inputs in the same chat are routed independently;
the offline fixture creates a task for each request and attaches a signal only
when it explicitly names an offered `@task-ID`.

- `REPLY` frames expose stable reply IDs, host-owned destinations and original
  public report facts. `MAIN_ERROR` exposes safe persisted main-router failures.
- The idempotent `ack_reply` control records direct consumption. Writing to
  stdout does not acknowledge a reply or prove external delivery, and this
  control cannot resolve an external send attempt.
- Reports and replies replay on restart with stable IDs. Exact steering and
  cancellation targets, independent task execution and controls while stdout
  is blocked are preserved. Local progress subscriptions remain separate from
  durable Thread routing subscriptions.
- `-main-context-bytes` bounds main-session context, defaulting to 1 MiB.
  Exceeding the budget records an explicit failure without automatic retry.

Stop old writers before upgrading a journal. Opening an existing journal with
this CLI performs a one-way main-session upgrade: legacy `Open` cannot write
it afterward. Completed reports, task identities and Worker/provider snapshots
are preserved. See the [CLI migration contract](../superagent-cli-main.md).

This release also fixes a stale-catalog regression test that counted delayed
MCP cancellation notifications as new tool traffic. It retains the zero-call,
zero-dispatch and zero-write assertions without changing runtime behavior.

The integrated changes passed Windows root/examples tests and vet, focused
toolset/CLI/SuperAgent race tests, and executable CLI replay/acknowledgement
checks. Live providers and external transports were not exercised. Builds
require Go 1.26.2 or newer; no dependencies were added.

