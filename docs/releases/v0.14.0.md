Native Responses tools, dynamic function declarations, and lower overhead in MCP, Codemode, and checkpoint paths.

## Changes

- Add opt-in native text and grammar tool inputs, with explicit prefer/require policies, host parsing, and tool-sampling capability resolution. Codemode can use native inputs while retaining its JSON function fallback.
- Preserve the position of dynamic Responses function declarations, including namespaces and replay identity. Fix declarations and system updates after failed history is filtered.
- Recognize additional gateway context-overflow errors without broadening unrelated error classification.
- Normalize Responses request context once and separate tool outcome preparation from validation while preserving execution, hook, and state-acceptance semantics.
- Reduce repeated hashing and serialization of owned MCP artifacts, cached catalog schemas, Codemode aliases and embedded WASM, and live approval bindings. Retain validation at external serialization and replay boundaries, including concurrent catalog reads.

## Upgrade notes

- Native tool sampling is initially enabled only for the exact `openai / gpt-6-astra / openai-responses` capability entry. Other combinations follow the requested fallback policy. See [native tool contracts](https://github.com/Icatme/pi-go/blob/v0.14.0/docs/native-tools.md).
- Native-capable dynamic tool history must be supplied in full. Requests using `previous_response_id` with that history fail before authentication hooks or network I/O, including tool removal, redefinition, and folded-system fallback. See [dynamic tool declarations](https://github.com/Icatme/pi-go/blob/v0.14.0/docs/dynamic-tool-anchors.md).
- The checkpoint v1 encoding, approval digests, and previously persisted partial decisions remain compatible. This release introduces no storage migration; the v0.13.0 session Storage and JSONL v2 requirements still apply.
- Go 1.26.2 or newer is required. Third-party dependency versions are unchanged.
