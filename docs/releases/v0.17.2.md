# v0.17.2 release candidate

This candidate refreshes CommandCode metadata and preserves structured Responses
error diagnostics. It does not add retries or claim to fix an observed JZ 502.

## Changes since v0.17.1

- Follow pi-commandcode-provider v0.7.10 / CommandCode CLI 1.88.0 capability
  metadata and reviewed display pricing. New models still require discovery;
  their endpoint and context limits are not guessed from capability metadata.
- Stop advertising retired free Ling and MiMo 2.5 models in the built-in catalog.
  Existing user configurations and cached catalogs are not deleted, and there
  is no automatic switch from a retired/free model to a paid model.
- Preserve decoded Responses error code/type details for protected diagnosis.
  These values remain untrusted; do not expose them in public APIs or logs.
  Retry ownership and execution safety are unchanged.

## Compatibility and downstream rollout

`ProviderFailure` adds exported `Code` and `Type` fields. Named-field literals
and ordinary field access remain compatible; external unkeyed struct literals
may need adjustment. Other protocols and older stored diagnostics return empty
values for the new fields. Go 1.26.2 or newer is required.
Applications pinning this version must run their own adapter contract tests;
source upgrade does not update running JZ or Bebebus instances. Relay continues
owning its durable retry policy, with no extra SDK or business-operation retry.

## Publication status

This file describes prepared sources, not a published tag. Automatic GitHub CI
was changed to manual-only at the owner's request; no run was dispatched.
Release-tag and asset-upload capability must be available before publication.
Source integration and a version constant do not establish module availability.
