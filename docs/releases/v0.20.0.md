# v0.20.0

This release adds the opt-in SuperAgent coordinator for Go applications. A
persistent main session routes requests to tasks with independent agent
snapshots, preserves progress and execution receipts, and records replies in a
durable outbox. Hosts supply their models, tools, authentication and permissions.
Builds require Go 1.26.2 or newer.

Users upgrading from the v0.19.0 downloadable release also receive the
`gpt-6.1-terra` Responses support introduced in the v0.19.1 source tag,
including text, image input, streaming and function calls.

- `OpenMain` supports independent tasks in the same chat, explicit task updates,
  steering and cancellation of an exact running invocation, frozen Thread
  fanout, and Worker clarification handbacks. `OpenMainBatch` processes bounded
  groups atomically. Authenticated admission policies filter ingress before it
  reaches model-visible state.
- Bounded public-history recall supports authenticated continuations across
  main callbacks. Replies can attach up to 16 structured report references.
  `Reply.Reports` preserves original terminal statuses, identities, review
  requirements and receipt facts in the requested order. `Reply.Report` carries
  the triggering Worker result. Citation validation uses the callback's frozen
  public view and reconstructs the same facts on journal replay.
- Controlled background tools add explicit start, inspect and stop lifecycles.
  A host may register the in-process backend or the durable Linux helper
  backend. Fixed-device and GitHub/IM adapters expose authenticated boundaries,
  and Watchdog offers read-only inspection plus separately authorized refreshes.

See the [SuperAgent API guide](../../superagent/README.md) and
[structured report reference contract](../superagent-m1d.md).

The public `Journal` and `LeasedJournal` interfaces provide the storage boundary
for `OpenMainJournal`. The bundled SQLite adapter supports competing processes
on one host with a reliable local filesystem, lease fencing, detached snapshots
and quiesced JSONL import. PostgreSQL and other shared database adapters belong
to the embedding application, which supplies its driver, schema, connection
lifecycle, lease renewal and validation. The root module's dependencies include
the SQLite driver, with PostgreSQL dependencies kept in host applications.
See the [journal interfaces](../../superagent/journal.go) and
[SQLite guide](../../superagent/sharedsqlite/README.md).

Recovery preserves uncertain execution and delivery outcomes for explicit
reconciliation. Reply claims fence individual delivery attempts, retain late
receipt evidence and prevent an uncertain send from being claimed again.
The merge review also fixed failure records carrying hidden delegations,
late background observations writing after coordinator shutdown, invalid
Unicode reaching durable reservations, stale-owner writes and helper/device
identity validation. Public history excludes rejected admissions, and GitHub
edited-comment authorization follows the authenticated editor.

Provider-authored tool arguments now retain their original JSON evidence long
enough to reject duplicate member names and invalid Unicode before execution.
Google and Mistral tool-call adapters participate in that validation.
Filesystem publication cleanup also releases staging resources before
inspecting host-supplied errors. Session storage adds strict JSONL opening and
read-only snapshots for recovery and import.

For applications tracking development snapshots, `MainDecision` now contains
the `ReportRefs` slice. Replace whole-struct comparisons or map keys with
explicit field comparisons or a separate comparable key. SuperAgent and this
type are new since the v0.19.1 release. Earlier development snapshots that
imported the PostgreSQL adapter must move that implementation into their host
application and use `OpenMainJournal`.

SQLite runtime targets are Linux, macOS and Windows on amd64/arm64, with
same-host local storage required. Durable helper execution is Linux-only.
Hosts own transport authentication, TLS, native tool isolation and external
effect fencing. Live model quality, production permissions, real devices and
cross-host database acceptance require validation in the embedding application.
Offline protocol, load and recovery fixtures provide reproducible tests of the
implemented boundaries. The helper's crash-recovery limits are documented in
the [helper guide](../../agent/background/helper/README.md).
