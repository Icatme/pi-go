# v0.22.0

SuperAgent now exposes `PiTaskAssessor` for hosts that own durable task admission
and need to classify one incoming request before dispatch. It selects `new`,
`attach`, `clarify` or `status` and independently suggests a `light`,
`conversation` or `task` workload.

- Hosts offer bounded candidates with opaque task IDs and explicit `CanAttach`
  eligibility. The assessor cannot invent a task, authorize execution or change
  a journal. Hosts retain context selection, model routing and persistence.
- Assessment makes one isolated model request. Business prompts, tools, history,
  resolvers and execution hooks are not inherited. The context budget includes
  the policy, input and decision-tool declaration; oversized input is rejected.
- Strict decision validation rejects unavailable targets, duplicate or unknown
  fields and malformed decisions. Provider failures and cancellation remain
  distinct from invalid input or protocol output.
- Cancellation and stream failures close and collect the stream once. A later
  successful result cannot override an earlier failure or return a decision.

Existing main-session routing, task attachment, history, progress subscriptions
and worker reports remain unchanged. See the [SuperAgent API](../../superagent/README.md)
and `ExamplePiTaskAssessor` for host integration.

Builds require Go 1.26.2 or newer; no dependencies were added. Validation uses
offline model fixtures, including cancellation/error and external API coverage;
live providers and external transports are not exercised.

```sh
go get github.com/Icatme/pi-go@v0.22.0
go install github.com/Icatme/pi-go/cmd/pi-superagent@v0.22.0
```

This version is published as a source tag.
