# M3d：宿主控制的主会话上下文压缩

基于 v0.22.0（`406e0ed`）。这是模型输入可用性切片，不是日志压缩、记忆真实性
保证或生产平台验收。没有新增依赖、数据库适配器或日志记录类型。

## 为什么需要

此前四种 Pi 主会话 Router 都保留全部旧消息。超过 `maxContextBytes` 时会明确
失败，但失败不替换已有快照，所以保存的历史足够大后，后续输入仍会反复失败。
公开历史的分页读取解决召回，不会自动减少模型快照里的历史和工具结果。

## 接口与触发

`PiMainRouter`、`PiMainBatchRouter`、`PiMainHistoryRouter` 和
`PiMainBatchHistoryRouter` 可接收一个可选 `MainContextCompactor`。原两参数调用
保持不启用压缩，传 `nil` 也不启用压缩。不继承 `AgentDefinition` 的执行、上下文或
请求改写 hooks，不隐式配置摘要模型。

回调收到当前输入之前的独立消息副本，返回 `MainContextCompaction`：

- `KeepFrom` 是保留旧消息后缀的起点；其之前的前缀被替换。
- `Summary` 是对该前缀的非空摘要。宿主负责摘要的完整性、准确性及使用的服务。
- 必须保留至少一个完整的旧轮次，不能切断原生工具调用和结果，也不能在未完成
  的决定后压缩。需要保留的近期事实由宿主选择，不能简单按固定消息条数截断。

只有完整的下一请求超预算时才调用回调，每次 Router 调用最多一次。检查包括
JSON 转义、系统提示、当前输入以及历史入口的工具声明。缩减后再次检查完整请求，
每次实际模型请求也受预算约束。当前输入或保留尾部本身过大、摘要仍过大，或
历史工具在本次推理中增长超限，均继续失败；不会反复压缩或在工具中途改写历史。

宿主可以使用本地确定性摘要、已授权的摘要服务或自行维护的摘要算法。这一接口
本身不批准任何外部服务、额度使用或隐私传输。未配置时没有额外模型推理或回调。
同步回调须遵守传入的取消信号；不应从回调关闭正在调用它的协调器。

## 权限与持久边界

摘要作为明确标记的“不可信历史上下文”用户消息保存，不成为系统提示。回调
不能改写当前输入、当前任务/运行候选、会话/Provider 身份、模型配置或工具权限。
回调输入的修改不影响保留的后缀。旧事实即使进入摘要也不是新任务、取消或更正
授权；协调器仍对本轮输入种类、候选目标和精确运行身份做原有检查。

返回快照仅在主会话给出合法决定后，通过原有 `main_decided` 或
`main_batch_decided` 原子提交。摘要失败、取消、panic、非法切点、超预算或非法
模型决定都不能单独提交压缩结果。失败输入沿用已有失败记录语义，不自动重跑。
关闭和失租沿用 Router 的取消与 writer fence；提交结果不确定时不报告成功。

事件、任务、投递、回复尝试、报告、审核状态、订阅、后台操作和公开历史引用
仍保存在原日志，身份不变。重开读取已提交的新快照，不回调摘要、不重派任务。
旧的历史也仍在日志中，所以本功能**不减少日志文件大小或重放成本**，不提供删除、
隐私擦除、跨重启游标或存储检查点。

摘要内容不能通过结构检查证明正确。宿主应保存必要的用户限制和未完成承诺，
需要精确旧事实时结合公开 `HistoryRef` 读取；不可把生成摘要当作副作用成功或
权限存在的证明。有关原始报告和回复的公开边界没有扩大。

## 兼容与验收

原两参数普通调用不变。四个构造函数增加了可变参数，因此将构造函数本身保存
为旧的精确两参数函数类型的调用方需要用两参数闭包包装；已返回的 Router 类型
不变。新快照仍使用现有 `agent.Message`，无需新 journal 格式。

预算计数同时修正了一处旧问题：预检原先漏计 Runner 注入的系统消息，普通入口
也未在实际模型请求处复核。现在计入系统消息和历史工具声明，并在真实请求边界
检查。曾按漏计值配置的紧预算可能开始被拒绝，应按完整请求调整，不能把旧的
错误预算上限视为兼容保证。

离线回归验证默认超限、显式压缩恢复、重复单条/批处理、完整历史工具对、错误切点、
摘要或输入过大、取消/错误/panic、回调副本隔离、当前输入/目标不变、重开后的
快照与回复身份。测试使用固定模型和本地临时日志，不请求真实模型或平台。

最终执行过的命令与审查结果记录在 PR 和共享工作记录。真实模型摘要质量、真实
token/费用、Windows/macOS 运行、生产平台与大规模存储性能不在本切片验收内。
