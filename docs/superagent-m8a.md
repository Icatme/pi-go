# M8a：只读 Watchdog 与持久复查证据

2026-11-05。基于未合并 draft #171 的精确树
`354a415d6f0f5c075116dc3bfa266e626801ea0e`；开发切片，未发布。

## 范围

`SuperAgent.CheckWatchdog` 检查一批既有任务，`RunWatchdog` 提供独立时钟循环，
宿主可把它放在独立 goroutine 中。`WatchdogStatus` 查询已提交的检查和下一游标。
两者都不默认选模型或访问服务；`Diagnose` 是可选、宿主提供的只读回调，验收
只用离线脚本。没有取消、重试、改派、Steer、发送、清除审核或创建新任务接口。

这是 M8 的只读首切片，不是完整 Watchdog 干预系统。授权修复动作、跨进程控制
命令、规则配置迁移/回退、自动通知和修复后效果核实留待后续。本切片保存异常
候选、判断依据、稳定诊断 ID、前次诊断 ID 和复查时间，重复巡检可看到连接或
任务状态的变化；这些观察本身不是执行任何修复的授权。

## 会话、调度与存储

- Watchdog 拥有独立 session/provider ID、最多 1 MiB 模型快照和固定策略版本。
  任务、主会话及 Watchdog 的快照不互借；合法 JSON 数字保真。
- 策略固定 interval、每批 1–32 个任务、空转窗口和最低 turn 数。首次使用持久
  保存策略，重开不能悄悄改变版本或阈值。配置迁移尚未实现。
- 同一协调器一次仅一轮检查。持久 round-robin 游标遍历 append-only 任务名单，
  每批的诊断、下一游标、下一检查时间和模型快照在同一条日志中原子提交。
- Watchdog 是独立会话和调度循环，不是第二个日志写者；沿用协调器唯一 writer
  与 M6 lease fence。失租/关闭取消回调，提交时再次检查上下文和存储所有权。
  `Close` 等待当前回调退出。宿主回调必须响应取消，不得从回调里关闭协调器。
- 已提交的检查在重启后不重复记录；未提交的**只读**探测/推理可以重做。时钟
  回拨不会提前重复巡检，时钟前跳本身也不会证明任务卡住。假时钟不控制租约。
- 观察输入在锁内复制，探测和模型回调在锁外运行。阻塞 Watchdog 不阻塞主会话
  或 Worker。返回时事实已变化则记录 `Stale=true`，只能作为历史观察使用，
  不能把它的 Class 当作任务当前状态。下一轮不继承 stale 的静默窗口。

## 诊断依据与安全边界

输入只含原始任务请求摘要、最近关联输入摘要、最近公开报告、固定状态/计数、
已准入后台操作的公开身份及审核事实。每段输入带持久 delivery 引用，重放核对
它确实属于该任务。`Goal` 是原始请求，不是最近结果，也不是对所有后续更正的
语义归纳；`LatestInput` 提供最近已关联输入。精确 steering 历史和完整长上下文
未注入，偏航只能作为有限上下文下的假说。

不传 Worker 快照、工具参数/结果、私有错误、凭证或完整历史。探针只收到已有
操作的 ID、任务、delivery、工具和固定状态，必须自己遵守只读、认证及权限边界。
`Probe` 明确返回 offline 才构成离线证据；超时、错误、panic 均为 unknown，
不自动重发 Start 或选择另一设备。

确定性分类：

- `needs_review`：前台或后台审核屏障存在，优先级最高；模型不能清除。
- `device_offline`：宿主对某个已准入操作提供明确离线证据。
- `tool_running`：工具生命周期未结束或后台操作仍 reserved/running。
- `queued`：任务等待调度；不会因等待很久就被判空转。
- `normal_slow`：运行/最终提交/取消请求尚未结算。仅耗时长或没有进度通知
  永远不会触发确定性空转判断，也不会造成取消。
- `idle_suspected`：同一进程、同一执行的观察窗口内出现至少配置数量的结束
  turn，且没有观察到工具结束或新公开终态。它仍是假说，不证明没有有效工作。
- `settled`：当前没有上述等待或审核条件，包括宿主复核后的 ready 状态。

模型只能对本批已有任务提出 `idle_suspected` 或 `drift_suspected`，附有限文本
依据。等待/工具/离线/审核事实不能被模型覆盖；已结束任务不能被模型标为空转。
非法任务、重复诊断、新业务动作或错误会话快照使本轮模型结果整体失败，保存
保守的确定性观察及 `ModelStatus=failed`，不会保存原始错误或产生业务动作。

运行进度计数不是成果证明。进程重开使用新的 RuntimeID，运行身份变化、工具
结束、公开终态变化或 stale 观察均重建计数基线，防止把重启归零视为卡住。

## 验收

先建立缺 API 的失败测试，再实施。覆盖：

- 空任务日志、批次分页、重开继续原游标/会话、同一已提交检查去重。
- 假时钟下慢任务、队列等待、工具执行、多 turn 空转、回拨与独立循环唤醒。
- Watchdog 推理被屏障阻塞时任务继续完成；过时结论标记为历史。
- 明确离线→在线复查；M4 重启未知效果保留审核与配额，错误不等于离线。
- 独立模型记忆、非法动作/快照、panic 脱敏、私有参数 canary 不进入诊断模型。
- 写失败不推进诊断/游标/快照；混合 envelope、伪造稳定来源、损坏游标、
  无会话或缺失快照的 completed 记录被重放拒绝。
- 实际 sharedsqlite 新 epoch 接管时迟到诊断不能落盘；旧 journal 的直接 append
  同样被 fence。底层既有子进程 kill/SIGSTOP/接管测试仍由全仓验收运行。
- 外部 Go 示例无需 CLI 或真实 provider；没有业务任务、回复或停止副作用。

最终命令及精确提交树在 PR 记录。PowerShell 在该远程容器不可用，使用 POSIX
shell 与 Linux amd64 Go 1.26.10。全仓 readonly tests、vet、race，Watchdog
race 重复 20 次，以及独立 examples tests/vet 均在最终代码上通过。

额外的 `go list -mod=readonly -m all` 全模块枚举因 `GOPROXY=off` 且部分间接
模块元数据未缓存而未通过；实际包测试、vet 和 examples 可用缓存完成，未改依赖。

## 未覆盖的部署条件

巡检共享同一授权域所有者，不是进程失联后仍独立运行的控制平面。宿主需要在
每次启动时显式调用 Run/Check；恢复不会自动启动模型或新的计费任务。检查历史
仍为追加日志，未提供压缩/保留策略或无限规模性能保证。没有真实服务、设备、
用户本机、模型/provider、新凭据、额外付费执行、手动 CI、合并或部署验证。
