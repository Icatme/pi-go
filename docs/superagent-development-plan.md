# SuperAgent 开发计划

2026-11-06 · 按已发布 v0.22.0（`406e0ed`）重新核对。根库提供公开的 `Journal`、`LeasedJournal` 接口与同主机 SQLite 实现，PostgreSQL 等后端由宿主实现和验收。各里程碑的实施与验证范围见对应切片记录。主入口为 `github.com/Icatme/pi-go/superagent`。

宿主服务启动时创建一个 SuperAgent。用户始终和同一个主 Agent 交互：主 Agent 可以直接回答、把独立任务交给不同 Pi Worker、把更正交给正在工作的 Worker，并在收到结果后决定如何向用户汇报。一个 Worker 等待模型、工具或设备期间，其他对话和任务仍可推进。

本文以《Super-agent 设计探索：迈向更自主的 Agent 系统》§2–§7 和当前实现为依据。下文保留完整目标；已交付范围与仍需开发或外部验收的范围以本节和对应切片记录为准，不能把原始目标清单全部当成待开发工作。

## 0. 当前结论与下一步

**设计范围已覆盖主会话、并行任务、异步工具、信道、共享状态、设备和监督，但不等于生产验收完成。** 原开发栈 #157–#191 已合并；v0.22.0 又新增宿主可复用的独立 `PiTaskAssessor`，不应重做这些能力。旧切片开头的“未合并”描述是当时的开发基线，不是当前分支状态。

| 领域 | 已在主干的能力 | 仍未完成的边界 |
| --- | --- | --- |
| M1–M2 | 持久主会话、精确更正/取消、回复尝试、结构化报告引用、同聊天多任务、冻结 fanout 与交回、投递身份；CLI 已使用主会话 | 自然语言摘要真实性与真实业务效果不能由这些协议保证 |
| M3 | 宿主准入、积压批处理、公开历史引用、超过 128 候选的召回、同协调器跨回调续页 | 主会话长上下文压缩；跨重启续页；宿主明确选择的工具结果公开；有界存储 |
| M4 | 异步工具、独立配额、原调用完成事件、批处理组合、可选耐久本地 helper | 真实宿主重启/断电、生产执行后端及跨主机验收 |
| M5 | IM 模拟协议、GitHub webhook/回信合同、签名与 HTTP 边界、回执/限流 | 真实平台权限和失败核实；邮件、文档、日程适配；持久 HTTP inbox |
| M6 | 公共 Journal/LeasedJournal、同机 SQLite 租约、旧 JSONL 导入、失租与未知提交屏障 | 保留所有身份的检查点/日志压缩；宿主自己的多主机存储及验收。PostgreSQL 不回到根库 |
| M7 | 固定授权设备协议、epoch fencing、原操作查询/停止、设备与 helper 崩溃恢复组合 | 自动设备选择/等待重连、真实认证和跨主机/断电验收 |
| M8 | 独立只读诊断、RunWatchdog 周期巡检；M8b 宿主单次授权的原操作 Inspect 与持久复查证据 | 干预后的定向复查/通知、授权修复动作、人工升级通知、配置版本迁移 |
| M9 | 离线基线、四入口小型协议对照、300 投递运行时负载、混合中断/恢复守恒 | 完整四策略 300 消息对照、持续到达率测量、真实模型 token/费用和最终发布验收 |

`PiTaskAssessor` 只为宿主输出 new/attach/clarify/status 与工作量建议，不替代上述协调器，也不执行或持久化任务。下游 JZBeacon 已固定 v0.22.0；宿主集成仍由宿主仓库负责，不因库的新功能自动改变旧 Agent 默认入口或 SuperAgent 的 slash 切换方式。

### 后续切片优先级

1. **M3d，主会话上下文压缩。** 优先解决历史只增不减、预算耗尽后后续输入持续失败的问题。显式选择宿主压缩回调，只替换旧历史前缀，保留完整近期轮次和工具对；当前输入、任务候选与运行身份不参与改写。压缩仅随合法决定一起提交，失败保留旧快照。四种 Pi 主会话入口共用该合同，默认仍拒绝超预算，不隐式调用额外模型。[本切片](superagent-m3d.md)。
2. **M6d，存储增长方案与验收。** 先固定检查点/导出导入的身份与重放合同，再实现一种可选后端；必须保留去重键、HistoryRef、未确认回复、审核状态、在途操作、订阅和租约 fence。模型上下文压缩不替代这项工作，也不删除原日志。先评估恢复时间与文件增长，避免无指标的复杂化。
3. **M8c，监督复查闭环。** 复用已有 RunWatchdog 周期巡检，补充 RefreshWatchdog 干预后的定向复查与通知证据，不另造普通巡检定时器。先只读，不把模型诊断变成新工作或修复授权。通用恢复动作独立设计、逐项授权。
4. **M9e，补全离线四策略对照。** 复用实际 API 和同一输入夹具，固定并发/工具耗时、记录任务正确率和真实运行计时。离线结果不冒充真实模型效果、token 或费用结论。
5. **宿主外部验收。** 平台、真实设备和数据库验证分开排期；真实模型/账户、额外额度、生产与数据库写入依赖明确授权和对应环境，不能成为上述纯库切片的隐含前置动作。

每个切片先确认主干和打开的 PR，保留一个明确的可验收目标，定向测试后运行相关全量检查并独立审查，再提交草稿 PR。没有重复实现、自动合并、发布或生产变更的隐含要求。

## 1. 范围与首个验收场景

**延期范围是 PDF §3.4 的主动发现和投机执行。** 例如群里有人泛泛提到一个问题，系统自行立项、试修并发布 PR，这条链路留到后续。显式请求、已委派任务的 CI 回调、异步工具完成、设备重连和 Watchdog 对既有任务的巡检均在本计划内。普通环境信号可留作上下文；启动新业务工作需要可追溯的用户请求或宿主已配置的委派。旧宿主自定义的 Router 策略要在升级说明中明确映射。

**第一个可用版本用同一聊天中的三句话验收。**

1. 用户说“分析昨晚的日志”。任务 A 开始，测试用通道把 A 的工具停在写入前。
2. 同一用户接着说“同时跑测试”。主 Agent 建立任务 B。B 在 A 释放前开始并完成，主 Agent 向原聊天交付 B 的结论。
3. 用户又说“日志只看最近一小时”。主 Agent 将更正送到 A。若 A 尚未在安全边界接收，界面只能显示已排队；若归属不清，主 Agent 在原聊天追问。任务 B 的输入和快照不含这条更正。
4. A 完成后主 Agent 根据 A 的报告回复。重投原消息、重启进程均得到相同的任务归属和交付记录。普通业务调用无需子任务 ID 或 `WaitIdle`；宿主仍可用精确的 `RunTarget` 控制特定执行。

## 3. 交付顺序

每个阶段按下列工作项拆成可单独验证的 PR。接口名在对应切片内根据现有调用方定稿。先做 M1、M2 的本地闭环；后续阶段以通过依赖项的验收为开工依据。

| 阶段 | PDF 对应 | 依赖 | 可验收的结果 |
| --- | --- | --- | --- |
| M1 主会话、Worker 汇报、统一回复 | §2 | 当前库 | 同一主会话能收件、委派、追问、答复，重开后接续 |
| M2 话题分流、订阅与交回 | §2.2、§3.2 | M1 | 同一聊天的独立请求并行，已知任务的明确更新直通 |
| M3 过滤、Router 批处理与链式召回 | §2.1、§3.1、§3.3 | M1、M2 的事件和投递身份 | 拥堵时合并推理，旧任务可按关联找回 |
| M4 异步工具与子任务 | §4.1 | M1 的事件回灌、M2 的调用归属 | 工具仍在运行时，同一 Worker 可以处理新输入 |
| M5 信道接入与对外交付 | §4.2 | M1 的回复记录、M2 的会话归属 | IM 发起、PR 评论跟进，主 Agent 在指定信道回复 |
| M6 共享状态与接管 | §5.1 | M1–M4 的持久记录格式 | 进程可替换，多实例争抢时每个任务只有一个有效执行所有者 |
| M7 远程设备执行 | §5.2 | M4、M6 | 已授权任务可选设备、等待重连、收回结果 |
| M8 独立 Watchdog | §6 | M3、M4、M6；设备用例依赖 M7 | 可识别卡住或偏航的既有任务，修复后复查 |
| M9 对照实验与发布验收 | §7 | 基线从 M1 前采集，最终验收依赖前述阶段 | 可重复比较吞吐、等待时间、模型成本和任务正确率 |

M3 的召回索引、M4 的后台执行器、M5 的协议适配可在事件身份稳定后分开开发。每次只由一项 PR 修改共享日志格式，先提交读写契约及重放测试，再接入使用方。

## 4. 实施工作项

### M1 · 让主 Agent 完成一次委派和回复

- **M1a，持久主会话。** 每个宿主授权域有一个 Router 快照和有序收件队列。第一版每次处理一项：用户消息，或由协调器根据 Worker 终态生成的结果事件。输入包含来源、会话、因果关联和获准公开的摘要。为 Router 配置独立的模型及上下文预算，只开放协调和读取能力。
- **M1b，决定与执行分开。** 主会话输出结构化决定，支持建任务、关联已有任务、发送更正、取消指定执行、直接答复、追问和忽略。程序校验目标、权限和本轮输入，在一次日志提交中写入已消费输入、更新后的 Router 快照、决定及待执行动作。调度器提交后执行。阻塞 Router 模型做一次推理时，宿主仍可提交输入，已确定归属的任务和精确取消继续推进。
- **M1c，回复独立交付。** 保存待发送回复、目的 Thread、稳定回复 ID、来源决定及送达状态。先用内存信道实现读取和确认。Worker 的结果报告保留真实成功、部分失败、已提交副作用和审核状态；主 Agent 可汇总多份报告，直接引用这些事实。回复确认和自身回显按身份过滤，防止重复回到 Router 触发派工。
- **验收。** 用离线脚本模型固定决定，验证“委派 → Worker 完成 → 主 Agent 回复”和“追问 → 用户补充 → 原任务继续”。在决定提交前、提交后动作执行前、发送后确认前分别中止进程。重开后逻辑任务和回复 ID 均唯一；外部发送结果不明时显示待核实。

### M2 · 分清“另起一件事”和“更正这件事”

- **M2a，区分聊天入口和任务入口。** 无明确任务指向的聊天请求交给主 Agent，即使这段聊天已经产生任务 A。带有任务关联的回复、链接到指定 PR 的评审更新等可直通对应 Worker。Router 仍能从日志看到快路径事件的摘要。宿主显式 `Steer` 和 `Abort` 保持精确目标；普通 `Submit` 的准入与 steering 的实际交付分别记账。持久更正关联原消息和任务；重启时结合已保存的任务输入判断是否已交付，归属或交付不明时请求核实，避免对任务的新一轮重复注入。
- **M2b，多对多投递。** 用 Thread 与任务的订阅关系替代单目标映射。一次外部输入只准入一次，入账时确定接收名单，每个目标拥有自己的投递记录和终态。保留每任务的事件顺序。允许 Worker 通过受控动作订阅、退订或把越界消息交回 Router；交回带原始事件、已处理范围和原因。相同原因反复交回时转主会话澄清。
- **M2c，报告与迁移。** 现有 `(source,event_id)` 继续作入站去重键。为多目标结果增加投递身份，更新 `ReportsSince` 消费方、CLI 和宿主示例的去重约定。旧日志中的单条绑定和报告可还原为单目标投递；已有任务和 Provider 会话沿用原身份。宿主监听进度的 `Subscribe` 与 Thread 路由订阅使用独立契约。
- **验收。** 执行第 1 节的完整对话；另让 A、B 同时订阅一个 PR，事件入账后 B 退订、C 加入。重开后该事件仍仅归 A、B，后续事件归 A、C。A 成功、B 中断时分别保留结论和回执。A 忙且用户转换话题时，B 的分派无需等待 A 判断或释放。

### M3 · 让 Router 在事件多、历史长时仍能判断

- **准入与语义过滤。** 在宿主适配边界配置来源、身份、群组、显式请求与既有任务关联规则；确定性噪声短路，其余候选进入 Router。规则版本、准入原因可查。无任务关联且无显式委派的信号默认只记录或忽略。
- **积压批处理。** 空闲时立即处理首条；上轮推理期间积压的事件按条数和输入预算组批。每项决定必须对应明确的输入 ID；处理重复、缺项、越权目标和过期订阅。只提交校验完整的决定组，失败组保留原输入及明确失败状态，释放调度槽让其他事件继续推进。精确取消走原生控制路径。
- **Inline、Spill 与链式召回。** 为 Trigger、Thread、Task、Worker 报告和长工具结果建立授权域内的稳定引用。注入时带摘要、必要相邻消息和相关 ID；大内容存储在窗口外，提供只读、分页、限量的模型工具。支持从当前消息查 Thread、任务、关联评审及旧报告；历史索引覆盖近期 128 个候选之外的任务。每一跳重新校验可见范围。
- **验收。** 故意阻塞第一次 Router 推理，然后递交一组独立和相关事件；断言下一次请求确实包含多条输入，且逐项结算。在超过 128 个任务的夹具中，从 IM 消息找回旧 PR 的指定结论；超预算按引用续读，其他授权域和未获准公开的工具输出均不可读取。

### M4 · 同一 Worker 内的异步工具

- **M4b 组合验收。** [批量主会话与后台工具](superagent-m4b.md) 核实 M6a 的 `OpenMainJournal` 已支持 `BatchRouter + Background`，补充混合积压、原生 Pi 协议、权限/停止/unknown 与失租回归；未复现运行时缺陷，不另造入口。
- **M4c 开发切片。** [耐久本地 helper](superagent-m4c.md) 提供可选宿主固定二进制注册、不可变操作与原始 epoch、停止恢复和耐久观测；隔离子进程验证协调器/helper 崩溃、同 ID 不重启和迟到提交。未知仍保留审核/配额；不含真实设备、生产或主机断电验收。

- **后台运行契约。** 在宿主明确注册的耗时命令、子任务上提供模型可调用的启动、查询和停止操作。先落盘运行身份、所属任务/调用、授权范围和资源配额，再返回 `Started`。执行体独立持有取消句柄和回执生命周期；后台任务占用独立的并发额度直至真实退出。首个实现用可控的本地执行后端。
- **完成事件。** 后台结束后，把结果或结果引用作为一条新事件投递给原任务，在合适的推理边界消费。记录原启动调用与完成事件的关联；保持 Provider 要求的一问一答工具消息顺序。同步工具沿用现有 Pi 语义，宿主可逐个选择异步能力。[现有执行工具](../agent/exectools/README.md) · [现有回执](../executionreceipt/README.md)
- **停止与恢复。** 区分停止单个后台操作、取消一次 Worker 执行、后台执行体已退出、外部效果已提交。支持停止先于启动确认、迟到完成、重复完成、任务改派，以及重启后查询仍在运行的后端。已发出且效果不明的操作进入核实流程。
- **验收。** 用屏障停住一项工具。工具返回 `Started` 后，同一 Worker 必须在屏障释放前完成一次新输入的推理。再让后端收到停止后仍提交一次写入。确认最终回执保留提交事实，配额在真实退出后释放，重复或迟到完成只送回原调用一次。

### M5 · 多信道收件与回信

- 定义可嵌入的入站归一化和出站发送契约。入站绑定宿主认证得到的身份、组织和 Thread；出站消费 M1 的回复记录，保存信道消息 ID、交付游标和确认。IM 生成简短的提问或结论；GitHub 评审、邮件和文档可承载较完整的变更与验证摘要。
- 分两批交付：先完成 IM 与 GitHub PR/评审的入站、回复、重复回调与跨来源关联；再接邮件往来、文档评论和已授权的日程事件。具体产品从宿主实际使用的平台选取。每种实现先通过同一套信道契约夹具，再用该平台的本地协议模拟器验证真实编解码和失败处理。
- **验收。** IM 发起请求，GitHub 评论修改要求，Worker 使用同一任务历史继续执行。分别验证原 Thread 收到适合该信道的答复、重复 webhook 不重复派工、平台限流后按其规则恢复。发送结果不明时按平台查询或标记待核实。对外只发送 Router 批准交付的内容。

### M6 · 状态独立于计算进程

- **M6a 当前实现。** [共享日志与授权域租约](superagent-m6a.md) 提供同机 SQLite 存储与替换进程接管，使用本地文件系统及可靠 OS 文件锁。多主机共享网络目录不在支持范围内；任务级分片、检查点与压缩仍待后续。
- **宿主扩展边界。** PostgreSQL 等后端由宿主实现公开的 [`Journal`、`LeasedJournal`](../superagent/journal.go)，通过 `OpenMainJournal` 和 `MainJournalOptions` 接入。宿主负责驱动、schema、连接、租约及后端验收。根库中的 PostgreSQL 实现和依赖已移除；[M6b](superagent-m6b.md) 保留为历史记录。

- 协调器存储契约已由 `LeasedJournal` 固定。每次追加须在同一事务核验未过期所有权 epoch 与预期日志头，`Header`/`Log` 返回分离值，失租或提交结果不确定时取消 `Context` 并停止写入。`Close` 只释放本所有者的 epoch，过期所有者不能续租。租约覆盖整个授权域。宿主采用其他数据库及驱动时，按部署环境核对维护活跃度、Go 版本、平台兼容性与替代方案。
- 以工作区/身份域划分主会话所有权。实例领取任务时获得有期限的租约与所有权版本；每次提交终态和动作都验证版本。交接支持优雅释放和租约到期。增加检查点、索引重建、日志压缩及旧 JSONL 导入；保留去重键、未确认动作、订阅、审核屏障和在途回执。
- **验收。** 在两个进程和同一测试数据库上抢占、杀进程、恢复网络、放回旧执行者。旧执行者不能提交新决定，外部已发生的迟到效果仍可按原调用核实。导入旧日志后逐项比对任务历史、报告、订阅和复核状态。弹性宿主替换实例后可以继续排队工作。

### M7 · 远程执行设备与重连

- **M7a 切片。** [固定授权设备执行协议](superagent-m7a.md) 提供独立设备注册表、宿主认证/epoch fencing 与 Start/Inspect/Stop 后台适配，已完成双模拟设备、双子进程及 M4/M6 离线集成；自动设备调度与真实设备接入仍待后续。
- **M7b 组合验收切片。** [耐久设备链路](superagent-m7b.md) 复用 M6a 同机租约、M7a HTTP endpoint 与 M4c helper，以独立子进程验证 endpoint 崩溃、旧 epoch 拒绝、丢确认、停止恢复、迟到提交、原 ID/单次启动与敏感输出隔离；未新增后端或生产 API。真实跨主机、主机重启/断电与生产认证仍未验收。

- 提供独立于模型供应商的设备注册与执行协议，以及一个可嵌入或由宿主启动的轻量设备端实现。设备发布在线状态和工具能力；宿主绑定设备身份、授权工作区、工具白名单及凭证访问边界。Scheduler 在已授权设备中选择目标，执行环境和本地凭证留在设备侧。
- 命令携带持久操作 ID，设备支持接收确认、状态查询、停止和结果回传。设备保存最少的去重/执行事实，主会话历史留在协调端。离线任务标明等待哪台设备；重连先查原操作状态，再继续**已授权**的工作。
- **验收。** 两台模拟设备只允许各自的工作区；再用两个独立进程跑一次真实协议。分别在接令前、提交效果后回执前断线，验证重连只执行一次或明确进入核实。云端重启不丢待办，设备凭证不会进入模型消息、回复或协调器日志。

### M8 · Watchdog 监督已委派任务

- **M8a 切片。** [只读 Watchdog 与持久复查证据](superagent-m8a.md) 提供独立会话/时钟、持久巡检游标、等待与审核优先的诊断、只读模型假说及重启/失租保护；授权修复执行器、配置迁移和自动通知仍待后续。
- **M8b 切片。** [宿主授权的原操作状态刷新](superagent-m8b.md) 已提供一次明确授权后的原 Backend/原 ID Inspect，持久绑定 finding、revision、原运行身份与复查条件；不启动、停止、重试或改派任务，不自动 Reconcile，也不自动安排下一次复查。

- 用独立会话、独立调度时钟和持久巡检游标，读取任务目标、最后有效进展、错误与审核状态。区分队列等待、设备离线、工具仍在运行、模型反复空转和任务偏航。先接入只读诊断，再开放有明确授权的恢复动作。
- 每次干预关联现有任务与异常记录，保存判断依据、动作和下一次复查条件。跨进程控制命令携带目标执行身份，交给当前持有租约的实例校验。可恢复连接、查询后端状态、提示偏航、向人请求复核；有外部副作用且结果不明时保留审核屏障。维护者可用自然语言查询故障或提出提示词/规则调整，生效须经过宿主授权、版本记录和可回退的配置更新。
- **验收。** 用假时钟和可控模型分别模拟正常慢任务、无进展循环、设备重连和接口恢复；验证不会取消正常慢任务，干预后会复查，重启不会重复执行同一修复。巡检过程中产生的新业务想法不启动任务。

### M9 · 实验、兼容与交付

- **M9a 切片。** [离线实验与验收基线](superagent-m9a.md) 提供固定 300 投递/20 请求、两种结构模拟各五次、Router 虚拟负载矩阵和真实 API 守恒/重放验收；两个单 Pi 提示策略、真实模型 token/性能与 M1 前历史基线明确缺失，不是完整 M9 或发布验收通过。
- **M9b 切片。** [真实运行时串行协议对照](superagent-m9b.md) 以同一 12 投递/2 任务夹具运行 PiMainRouter/PiWorker 与两种提示的单 Pi+宿主子任务队列，共四入口各五次；核对事件、工具回执、真实工具体效果、回复、任务历史与完成后重开。离线脚本不证明提示效应、并发性能或真实模型成本，完整 300 消息对照仍缺失。
- **M9c–M9d 开发切片。** [M9c](superagent-m9c.md) 增加实际 API 的 300 投递分阶段离线并发负载；[M9d](superagent-m9d.md) 另用 35 投递的有界交错夹具验证积压中的精确取消、fanout、更正、提交后失败及一次进程强制退出后的守恒。两者不是持续到达率性能实验、四策略完整对照或真实模型费用测量，最终 M9 验收仍未完成。


- **§7.1 调度对照。** 开发前留存当前库的基线。正式实验固定一组约 300 条消息（约 20 个工作请求，另含跟进、停止、噪声、CI 和同聊天多话题）。对比四组：完整方案、关闭订阅直通、单 Pi Agent 加子任务工具使用中性提示、同一单 Agent 优先委派。每组重复五次，固定工具耗时和并发预算。保存逐事件记录、正确完成数、实际委派数、错派和漏派、首次有效回复延迟、任务完成 p50/p95、累计完成曲线、模型调用与 token。
- **§7.2 Router 批处理压测。** 固定模拟 Worker，控制冷事件到达率从每分钟约 1 条升至 40 条，对比逐条与批处理。分别记录队列等待、实际批大小、每批推理时长、每项决策分摊时长、吞吐和错误。先用离线模型验事件守恒及去重，再按授权用真实 Router 模型测量推理成本。PDF 的耗时和倍数仅作为实验方法参考。
- 每个阶段先跑涉及包的定向回归，再运行 `go test -mod=readonly ./...` 和 `go vet -mod=readonly ./...`；改并发、持久化和设备生命周期时，在 Linux 对受影响包执行 `go test -race -count=1`。发布前运行外部包的 Go 嵌入示例、旧日志升级、双进程接管和跨信道交付测试，并记录已验证的平台与真实服务范围。

## 5. 接口演进与实施边界

- **Go 库与包方向。** `superagent` 负责任务、全局协调和回复；`agent` 负责单会话执行；`pkg/pigo` 负责模型协议。信道、数据库、设备属于可选适配器。宿主可只用本地库，或自行组合服务部署。
- **迁移。** M1 第一项 PR 盘点 `Open/Router/Worker`、外部包示例、CLI 及日志读取方。单事件 `Router` 的返回值表达不了回复和多目标动作，随切片给出新的直接调用方式和明确迁移说明。避免永久并行维护两套调度器。旧日志读取、事件去重和滚动升级的单写者边界分别用夹具验收。
- **副作用。** 每个决定、投递、回复、后台操作和设备命令都有稳定身份。内部重复事件可去重；外部平台支持幂等时复用同一键，无法确认时查询或交由 `Reconcile` 核实。工具“已返回”和“已提交效果”继续分别记录。
- **开放问题。** PDF §8 的 Router 分片、跨月记忆评测和跨组织 A2A 保留为研究项；本轮以单授权域的常驻主 Agent 为交付单位。权限隔离、可干预执行和敏感数据边界已纳入上述各阶段验收。

**最初的 M1a 验收起点（已交付）。** 第一份代码变更采用可复现的失败用例：在没有 CLI 的 Go 宿主内，Worker 报告完成后，应唤醒原主会话生成一条可确认的回复，重开日志后仍能关联这次委派。跑通该闭环再扩展分流与并发。

该首个闭环现已由 `OpenMain` 和外部包回归测试覆盖，Linux 离线测试、race 与 vet 已通过；接口、迁移边界及具体验证命令见 [M1a 交付记录](superagent-m1a.md)。M1b 现已补充结构化更正、精确取消、追问，以及决定提交后执行和动作重放边界，见 [M1b 交付记录](superagent-m1b.md)。M1c 已补充精确回复发送尝试、未知结果核实、证明未送达后的安全重试，以及确认与自身回显身份过滤，见 [M1c 交付记录](superagent-m1c.md)。M2a 已将普通聊天 Submit 与宿主明确关联的 SubmitTask 分开，并保留更正的精确执行归属与已保存输入证据，见 [M2a 交付记录](superagent-m2a.md)。M2b 已冻结多目标投递名单并提供受控交回，见 [M2b 交付记录](superagent-m2b.md)。M2c 已补充跨重放稳定的显式投递身份、ReportsSince 消费方/CLI/外部 Go 示例及旧日志迁移契约，见 [M2c 交付记录](superagent-m2c.md)。M3a 已补充可审计宿主准入门、按条数/输入预算的 Router 积压批处理、逐输入 ID 原子结算和失败隔离，见 [M3a 交付记录](superagent-m3a.md)。M3b 已补充授权域内稳定公开历史引用、冻结分页、超过 128 候选的链式召回，以及可选只读 Pi 模型工具，见 [M3b 交付记录](superagent-m3b.md)；M3c 已补充同一协调器内跨回调认证续页、精确公开内容版本核验和失租即时读屏障，见 [M3c 交付记录](superagent-m3c.md)。重启后的持久续页、显式工具原文公开、历史压缩与有界存储仍待后续。M1d 已补充同授权域公开报告的有界结构化多引用、原始终态事实附带和可恢复回复，见 [M1d 记录](superagent-m1d.md)；不验证自然语言摘要真实性，不自动向信道追加事实，也不扩大公开范围。真实信道验收仍待后续完成。这些切片现已合并并包含在 v0.22.0 中；各文档中的测试记录保留其当时的范围，不能据此宣称真实宿主服务已验收或部署。
